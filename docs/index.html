THE PROBLEM

Two menus. Three clicks. Every time.

To change effort in Claude Code you open the model picker, find Effort, open its submenu, then choose. Model has its own path, with older models hidden under More models. Usage means typing a command and dismissing it. You do this all day.

A NOTE FOR THE CLAUDE CODE TEAM

Model and effort should be one control.

Today they are two separate flows inside one nested menu. Changing effort takes three actions, the usage readout is a command you type, and older models hide behind a second submenu that you have to hover your way into.

What would fix it: one picker with model and effort side by side, a visible usage meter, and a keyboard shortcut for each. Until then, this mod does it with a band and a click.

FAQ

Quick answers.

Does it change how Claude answers?

Only when you ask it to. A chip click sets the model or effort for your next requests, and your own choice in the built-in picker wins again as soon as you make one. The built-in picker keeps showing the session's own setting.

Does it work on API billing?

Yes. With no plan limits to track, the band shows session cost instead of the usage bar.

Does it send my data anywhere?

No. It runs inside Claude Code and reads local session state. The dev server count uses a local lsof check.

How do I remove it?

claude plugin uninstall claudius-modulus@claudius-modulus

Is the click estimate real?

It is an estimate from counting the actions in the built-in menus, with the assumptions shown above. It is not measured telemetry.
